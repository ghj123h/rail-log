# 逐秒行车志（rail-log）

一个 GitHub Pages 网站保存多次列车运行记录，共用互动图表与实测线路图，每次只新增记录数据。

- 首页：<https://ghj123h.github.io/rail-log/>
- G797 示例：<https://ghj123h.github.io/rail-log/viewer.html?id=260923162858>

## 使用

首页直接展示归档指标、全网实测总线路图、线路合集入口（如京津城际合集）以及“其他线路的运转”卡片列表；卡片按视口懒加载速度缩略曲线、峰值速度与积分里程，并支持按车次、车站或日期实时筛选。

线路合集页（如 `collection.html?id=jingjin`）展示该合集全部成员汇总的合集线路图（含全部沿途车站）与逐趟卡片。

每趟运转详情页（`viewer.html?id=<ID>`）均包含：
- **逐秒速度图**：按 `< 200` / `200–250` / `250–300` / `300–340` / `≥ 340 km/h` 五档着色速度曲线，并附带速度精度置信色带、分档占比条、峰值图钉、阈值虚线与停站/通过区段标注。支持拖拽框选放大、滚轮缩放、`Shift+拖拽`平移、键盘快捷键、“后退一步”历史回溯，以及 `#w=<start>-<end>` URL 窗口直达与刷新恢复。
- **区间记录**：列出沿途停车与通过标记（`source: "inferred"` 显示“事后推算”）、历时、通过区间平均速度及距上一标记的时长与积分里程；点击任意行可同步缩放到对应时段。
- **沿途线路图**：所有运转页（包括合集成员）均绘制单趟实测线路图。速度图缩放时会高亮线路图上的对应区段，悬停速度图或线路轨迹时两图光标双向联动。页面统一使用北京时间（UTC+8）。

点击首页或合集卡片进入详情页。在速度图上直接拖拽即可框选放大特定时段，滚轮缩放、`Shift+拖拽`平移，点击“后退一步”或按 Backspace 退回上一视图，双击或点击“全程”还原，URL `#w=` 自动记录当前时段窗口。

首页的“总线路图”汇总目录中除普速记录以外的实测轨迹，共线记录以同一线色合并绘制，同一车站只标一次。仅显示各记录的起止站，以及这些记录实际形成分岔、汇合或交叉的车站；普通途经站的圆点和站名均不显示。单纯共线不会增加标注，未覆盖分支的现实枢纽与没有共同车站的立交交叉也不增加标注。交汇关系按完整沿途站序识别，不使用稀疏的停车、通过标记，也不按地图上轨迹的几何交点推断。

总图站名在圆点四周自动选择位置，减少文字重叠，不套用单次记录图的曲线外侧规则。总图沿用现有底图、河流、缩放和平移操作，实测轨迹的缺口保持断开；新增记录并更新目录后，总图自动包含新记录。汇总所需的任意线路数据载入失败时，总图显示错误，避免静默漏掉记录，首页目录仍可使用。

每条记录的“线路图”按本次线路裁切，绘制 GNSS 轨迹，缺少定位的区段留空，不连接或补画铁路走向。底图显示中国大陆地级市、自治州和直辖市边界，采用中国方面的国界口径；省界（含直辖市边界）使用粗实线，地级行政边界使用细线。行政区域不填色，不标行政区名称，直辖市不再细分区县。线路沿途所有车站均标注位置和站名，包括不停靠的车站；车站附近有可用 GNSS 时据此定位，其他车站采用公开资料中的位置。

底图以蓝色绘制黄河、长江干流，不绘制其支流；河道终点按底图河口海岸线对齐。GNSS 轨迹与车站标记默认采用琥珀色（`#ffb547`），线路图不显示图例。

站名根据当前显示比例下附近轨迹的走向，沿尽量垂直于轨迹的方向偏移，文字保持水平。判断方向时，在站点前后各约 16 像素范围取轨迹的净位移，并保留至少 300 米的空间范围，减少停车定位漂移的影响；缺少可用轨迹时，参考附近车站的走向。放大、缩小及窗口尺寸变化后重新计算方向，整条线路保持同一行进侧。文字朝向站点的边或角保持约 9 像素间距，接近水平或竖直方向时平滑过渡到居中对齐，纵向偏移不随站名长度增加。断点两侧的实测点仅用于判断标注方向，不补画缺失轨迹。

石家庄站名固定置于车站锚点正左侧，文字右边缘距锚点约 18 像素；该规定适用于单次线路图和总图，缩放及窗口尺寸变化后仍保持固定距离，不叠加矩形宽度。

线路图容器的高度随裁切后轨迹与车站范围的投影宽高比、可用页面宽度自动计算，并设置上下限：桌面端最小高度沿用最初的 `clamp(380px, 65vh, 680px)`，手机端沿用 480px，最大高度为浏览器可视区域高度（100vh）；可视区域小于上述最小高度时，优先限制在可视区域内。轨迹在实际容器中等比显示，保留站名边距。支持滚轮、加减按钮缩放和拖动平移，双击或点击“全程”还原。站名字号保持不变，不使用引导线，不因重叠隐藏站名；缩小时站名可以重叠。

首页按线路合集和独立记录组织目录。京津城际合集入口为 `collection.html?id=jingjin`，成员按日期从新到旧排列，可直接打开各趟详情。

新增京津城际记录后，将记录 ID 加入 `records/collections.json` 中 `jingjin` 的 `recordIds`，即可归入合集；记录数量和最近更新日期由目录自动计算。重建记录目录不会覆盖合集配置。

悬停速度曲线可查看北京时间、速度和速度精度，并在线路图同步显示当前位置光标；悬停线路轨迹亦可在速度图上显示对应时刻读数。停车与通过区间直接叠绘在速度图中，点击“区间记录”表格任意行即可缩放定位到对应时段并高亮线路图区间。页面只读，不提供新增、编辑或删除标记的功能。

通过区间的悬停详情与区间列表显示平均速度，按起止时间内（含端点）的原始速度采样取算术平均值，单位为 km/h，保留一位或两位小数；无采样时显示“无采样记录”，采样缺失时注明“采样不完整”。通过时间点不计算区间平均速度，停车区间不显示平均速度。区间区段着色与标记类型一致：停车为紫罗兰（`#b4a7ff`），通过为浅米白（`#e8e6df`）。

所有记录共用五档速度色阶（km/h）：`[0, 200)` 蓝灰（`#7c8db5`）、`[200, 250)` 青蓝（`#3fc1c9`）、`[250, 300)` 浅绿（`#9be564`）、`[300, 340)` 暖黄（`#ffd166`）、`[340, +∞)` 玫红（`#ff5c8a`）。速度曲线、阈值虚线、档位组成条、峰值提示与通过区间均速均按数值着色；边界值进入下一档。速度精度（± 数值）保留中性色。

## 新增运行记录

需要 Python 3，无第三方 Python 依赖。原始日志放在本地仓库之外。

```powershell
python tools/manage_records.py import "原始日志路径.txt" --train G123 --origin 始发站 --destination 终到站 --partial
```

速度导入脚本从 GNSS Logger 的 `Fix` 记录读取 `UnixTimeMillis`、`SpeedMps` 和 `SpeedAccuracyMps`，生成的速度采样仅保存时间、速度和精度。线路图另外保存本次线路的 GNSS 经纬度及车站位置；原始日志仍保留在本地，不纳入网站仓库。纯 NMEA 如果没有速度精度字段，无法用于速度导入命令。

记录 ID 默认从 `gnss_log_YYYY_MM_DD_HH_MM_SS.txt` 文件名读取；其他文件名请添加 `--id YYMMDDHHMMSS`。只有记录不完整时才使用 `--partial`。

导入会生成 `records/<ID>.json` 并更新目录。先本地检查，然后提交并推送：

```powershell
git add records
git commit -m "Add running record"
git push
```

记录内容在本地 JSON 文件中维护，再经复核后发布。如果添加、删除记录，或修改车次、展示区间、`beta` 等首页摘要信息，重新生成目录：

```powershell
python tools/manage_records.py rebuild
```

仅修改已有记录内的停车、通过标记时，首页摘要不变，不需要重建目录。

## 本地预览

```powershell
python -m http.server 8766 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8766/>。本地预览通过此服务加载站点目录内的脚本、记录和地图数据。

```text
assets/ui/common.js        共享格式化、统计、五档配色与缩略图组件（RL）
assets/ui/home.js          首页与合集页逻辑
assets/ui/run.js           单趟详情页速度图、框选、区间表与地图联动逻辑
assets/ui/icon.svg         站点图标
assets/route-map.js        共用 SVG 线路图绘制引擎与光标/区段高亮联动

assets/maps/               行政边界、河流底图与来源说明
assets/maps/major-rivers.geojson  黄河、长江干流的 WGS84 线数据
assets/maps/RIVERS.md      河流来源与处理说明

records/collections.json   合集说明与记录 ID
records/<ID>.json          一次运行的数据与标记
records/<ID>.route.json    本次运行的 GNSS 轨迹与沿途车站

tools/test_network_map_data.cjs 总线路图数据检查（node tools/test_network_map_data.cjs）
tools/route_stations.json  各次线路的沿途车站配置
```

每条记录包含 `id`、`title`、`train`、`origin`、`destination`、`partial`、`beta`、`logStart`、`logEnd`、`sampleIntervalMs`、`samples` 和 `events`。`beta` 为 `true` 时显示 Beta 标识，缺省或为 `false` 时不显示。

线路图数据独立保存为 `records/<ID>.route.json`，由查看器按记录 ID 读取。行政边界与河流使用共享底图。线路图与速度图分别载入，线路图加载失败时仍可查看速度与区间。

有站台或到发线几何依据的车站使用定向矩形，`stations[].platform.corners` 保存 WGS84 显示包络角点。纵向保留站台长度，左右边界包住全部站台并距最外侧到发线至少20米；到发线只取站台长度内的片段，缺少到发线时保留站台包络。原车站锚点保持不变，左右补足量可不同。既无站台几何也无到发线的车站保留原圆点及坐标；不以单条正线或车站节点投影虚构站台范围。单次线路图、首页总图和合集地图使用同一绘制组件。原始几何、到发线对象、来源、默认尺寸和屏幕最小尺寸见 [车站站台范围说明](assets/maps/STATIONS.md)。

线路图数据包含 `id`、`coordinateSystem: "WGS84"`、`segments` 和 `stations`。每段轨迹保存为 `[[lon, lat, t], ...]`，不同连续定位段分别保存，不跨缺失区段连线；圆点车站保存为 `{name, lon, lat}`，矩形车站另有 `platform: {corners: [[lon, lat], ...]}`。底图来源与坐标转换见 [地图来源说明](assets/maps/README.md)，河流来源与处理见 [河流说明](assets/maps/RIVERS.md)，公开车站资料链接保存在 `tools/route_stations.json`。

从工作区原始日志生成或更新线路图：

```powershell
python tools/build_route_maps.py
python tools/build_route_maps.py --id 260923162858
```

生成器使用 `tools/route_stations.json` 维护各次线路的沿途车站，根据原始日志生成对应轨迹与站点位置；仅更新线路图不改变速度采样和时间标记。

`samples` 的每个元素为 `{t, v, a}`：UTC Unix 毫秒时间戳、km/h 速度、km/h 速度不确定度。`events` 的每个元素为 `{id, name, type, start, end}`，`type` 为 `pass` 或 `stop`，起止为 UTC Unix 毫秒时间戳。页面显示北京时间 UTC+8，支持跨日期。

经记录者要求事后推算的标记仅在标准区间字段之外保存 `source: "inferred"`。不保存 `note`、`reference` 或记录级推算说明。区间表和悬停详情显示“事后推算”标识。G1985 的高邮北、G797 的滕州东和枣庄标记采用该来源标识。

C2123 的永乐通过区间同样标为“事后推算”：2026-10-18 18:55:34—18:55:40，不保留推算说明。

曲线保留清理后采样的原始数值，不做平滑。超过正常采样间隔 1.5 倍的间断（含清理产生的空缺）留空。色带为速度 ± 设备报告的速度精度（约 68% 置信水平），下限取 0。区间平均速度使用保留的采样计算，空缺继续标识“采样不完整”。

清理工具默认只审计，添加 `--apply` 才修改网页数据：
