# Rail Log · 运转记录册

一个 GitHub Pages 网站保存多次列车运行记录，共用互动图表，每次只新增记录数据。

- 首页：<https://ghj123h.github.io/rail-log/>
- G797 示例：<https://ghj123h.github.io/rail-log/viewer.html?id=260923162858>

## 使用

点击首页记录进入图表。滚轮或横向框选缩放时间轴，切换“拖动平移”查看相邻时段；双击或点击“全程”还原。

首页的“总线路图”汇总目录中全部运行记录的实测轨迹，共线记录以同一线色合并绘制，同一车站只标一次。仅显示各记录的起止站，以及这些记录实际形成分岔、汇合或交叉的车站；普通途经站的圆点和站名均不显示。单纯共线不会增加标注，未覆盖分支的现实枢纽与没有共同车站的立交交叉也不增加标注。交汇关系按完整沿途站序识别，不使用稀疏的停车、通过标记，也不按地图上轨迹的几何交点推断。

总图站名在圆点四周自动选择位置，减少文字重叠，不套用单次记录图的曲线外侧规则。总图沿用现有底图、河流、缩放和平移操作，实测轨迹的缺口保持断开；新增记录并更新目录后，总图自动包含新记录。汇总所需的任意线路数据载入失败时，总图显示错误，避免静默漏掉记录，首页目录仍可使用。

每条记录的“线路图”按本次线路裁切，绘制 GNSS 轨迹，缺少定位的区段留空，不连接或补画铁路走向。底图显示中国大陆地级市、自治州和直辖市边界，采用中国方面的国界口径；省界（含直辖市边界）使用粗实线，地级行政边界使用细线。行政区域不填色，不标行政区名称，直辖市不再细分区县。线路沿途所有车站均标注位置和站名，包括不停靠的车站；车站附近有可用 GNSS 时据此定位，其他车站采用公开资料中的位置。

底图以蓝色绘制黄河、长江干流，不绘制其支流；河道终点按底图河口海岸线对齐。GNSS 轨迹与车站标记采用朱红色（`#c44b2d`），线路图不显示图例。

站名根据当前显示比例下附近轨迹的走向，沿尽量垂直于轨迹的方向偏移，文字保持水平。判断方向时，在站点前后各约 16 像素范围取轨迹的净位移，并保留至少 300 米的空间范围，减少停车定位漂移的影响；缺少可用轨迹时，参考附近车站的走向。放大、缩小及窗口尺寸变化后重新计算方向，整条线路保持同一行进侧。文字朝向站点的边或角保持约 9 像素间距，接近水平或竖直方向时平滑过渡到居中对齐，纵向偏移不随站名长度增加。断点两侧的实测点仅用于判断标注方向，不补画缺失轨迹。

线路图容器的高度随裁切后轨迹与车站范围的投影宽高比、可用页面宽度自动计算，并设置上下限：桌面端最小高度沿用最初的 `clamp(380px, 65vh, 680px)`，手机端沿用 480px，最大高度为浏览器可视区域高度（100vh）；可视区域小于上述最小高度时，优先限制在可视区域内。轨迹在实际容器中等比显示，保留站名边距。支持滚轮、加减按钮缩放和拖动平移，双击或点击“全程”还原。站名字号保持不变，不使用引导线，不因重叠隐藏站名；缩小时站名可以重叠。

首页的“线路合集”集中展示同一线路的运转，合集内按日期从新到旧排列，未归入合集的记录显示在“其他运行记录”。京津城际合集入口为 `collection.html?id=jingjin`，目前收录 C2123（2026-10-18）、C2613（2026-10-12）、C2031（2026-10-10）的北京南—武清记录，以及 C2568（2026-10-17）的武清—北京南记录。合集引用原有记录，详情页地址和数据保持一致。

新增京津城际记录后，将记录 ID 加入 `records/collections.json` 中 `jingjin` 的 `recordIds`，即可归入合集；记录数量和最近更新日期由目录自动计算。重建记录目录不会覆盖合集配置。

悬停速度曲线可查看北京时间、速度和速度精度；通过与停车标记放在独立时间带，悬停才显示名称和起止时间。展开“区间标记”可查看时间点或区间，点击“查看”可放大到对应时段。页面只读，不提供新增、编辑或删除标记的功能。

通过区间的悬停详情与区间列表显示平均速度，按起止时间内（含端点）的原始速度采样取算术平均值，单位为 km/h，保留两位小数；无采样时显示“无采样记录”，采样缺失时注明“采样不完整”。通过时间点不计算区间平均速度，停车区间不显示平均速度。悬停高亮与标记类型一致：通过为紫色，停车为绿色。

所有记录共用五阶速度色阶（km/h）：`[0, 200)` 蓝、`[200, 250)` 绿、`[250, 300)` 黄、`[300, 340)` 橙、`[340, +∞)` 红。实时速度、通过区间平均速度、上下范围端点及速度轴刻度均按数值着色，折线图背景使用相同色阶的浅色横向色带。保留两位小数的文本按显示数值归档；边界值进入下一档。速度精度（± 数值）保留中性色，曲线周围的精度色带沿用原样。导出的离线网页使用相同配色。

- **导出记录数据**：下载包含全部速度点、区间标记和线路图数据的 `YYMMDDHHMMSS.json` 副本。线路图载入失败时仍可下载速度与区间数据。
- **保存离线网页**：将图表组件、速度与区间数据、GNSS 轨迹、车站、行政边界与河流底图打包为单文件 HTML，可用系统浏览器离线打开；线路图未能载入时会提示保存失败。

G797 保留 Beta 标识，其两段通过区间已由测试数据改为事后推算：滕州东站 16:36:22–16:36:29，枣庄站 16:44:11–16:44:18（2026-09-23 北京时间）。两站均按 450 米站台长度、原始 GNSS 轨迹和速度计算，近似以最接近高德站点的时刻作为站台纵向中点，起止向外取整到秒，页面显示“事后推算”。Beta 标识由每条记录的 `beta` 字段决定，首页和详情页一致；新导入记录默认不显示。

G797 是起点未确定的部分记录，`origin` 留空，页面显示“—徐州东”；单次线路图与总图均不标曲阜东，也不将第一个已知途经站当成起点。总线路图默认收起，首次展开后载入，再次展开保留缩放状态。

京津城际合集的路线图同样默认收起，汇总 `records/collections.json` 中该合集成员的原始轨迹并标注全部沿途车站。目前覆盖北京南—武清；今后将武清以东的运行记录加入合集后，地图随实际记录范围延伸。合集内各次记录的详情页与新导出的离线网页只显示速度图和区间标记，路线图统一在合集页查看；各次轨迹文件继续供合集与首页总图使用。

## 新增运行记录

需要 Python 3，无第三方 Python 依赖。原始日志放在本地仓库之外。

```powershell
python tools/manage_records.py import "原始日志路径.txt" --train G123 --origin 始发站 --destination 终到站 --partial
```

速度导入脚本从 GNSS Logger 的 `Fix` 记录读取 `UnixTimeMillis`、`SpeedMps` 和 `SpeedAccuracyMps`，生成的速度采样仅保存时间、速度和精度。线路图另外保存本次线路的 GNSS 经纬度及车站位置；原始日志仍保留在本地，不纳入网站仓库。纯 NMEA 如果没有速度精度字段，无法用于速度导入命令。

记录 ID 默认从 `gnss_log_YYYY_MM_DD_HH_MM_SS.txt` 文件名读取；其他文件名请添加 `--id YYMMDDHHMMSS`。只有记录不完整时才使用 `--partial`。

导入会生成 `records/<ID>.json` 并更新目录。先本地检查，然后提交并推送：

```powershell
git add records
git commit -m "Add running record"
git push
```

记录内容在本地 JSON 文件中维护，再经复核后发布。如果添加、删除记录，或修改车次、展示区间、`beta` 等首页摘要信息，重新生成目录：

```powershell
python tools/manage_records.py rebuild
```

仅修改已有记录内的停车、通过标记时，首页摘要不变，不需要重建目录。

## 本地预览

```powershell
python -m http.server 8766 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8766/>。网站版本通过 HTTP 加载 JSON；离线使用请从记录页下载单文件 HTML。

## 文件结构

```text
index.html                 记录目录
collection.html            线路合集目录
viewer.html                共用查看器
assets/                    图表与线路图脚本、样式、ECharts 和第三方许可
assets/maps/               行政边界、河流底图与来源说明
assets/maps/major-rivers.geojson  黄河、长江干流的 WGS84 线数据
assets/maps/RIVERS.md      河流来源与处理说明
records/index.json         首页摘要
records/collections.json   合集说明与记录 ID
records/<ID>.json          一次运行的数据与标记
records/<ID>.route.json    本次运行的 GNSS 轨迹与沿途车站
tools/manage_records.py    导入日志与更新目录
tools/build_route_maps.py  从本地日志生成线路图数据
assets/network-map-data.js 总线路图数据汇总与交汇站筛选
assets/network-map.js      首页总线路图与合集路线图载入
tools/test_network_map_data.cjs 总线路图数据检查（node tools/test_network_map_data.cjs）
tools/route_stations.json  各次线路的沿途车站配置
```

每条记录包含 `id`、`title`、`train`、`origin`、`destination`、`partial`、`beta`、`logStart`、`logEnd`、`sampleIntervalMs`、`samples` 和 `events`。`beta` 为 `true` 时显示 Beta 标识，缺省或为 `false` 时不显示。

线路图数据独立保存为 `records/<ID>.route.json`，由查看器按记录 ID 读取；导出记录时嵌入 `routeMap` 字段。行政边界与河流使用共享底图，离线网页将其分别嵌入 `window.ROUTE_BASEMAP` 和 `window.ROUTE_RIVERS`，无需联网读取地图、河流或轨迹。线路图与速度图分别载入，线路图错误不影响速度图、区间查看与记录数据下载。

线路图数据包含 `id`、`coordinateSystem: "WGS84"`、`segments` 和 `stations`。每段轨迹保存为 `[[lon, lat, t], ...]`，不同连续定位段分别保存，不跨缺失区段连线；车站保存为 `{name, lon, lat}`。底图来源与坐标转换见 [地图来源说明](assets/maps/README.md)，河流来源与处理见 [河流说明](assets/maps/RIVERS.md)，公开车站资料链接保存在 `tools/route_stations.json`。

从工作区原始日志生成或更新线路图：

```powershell
python tools/build_route_maps.py
python tools/build_route_maps.py --id 260923162858
```

生成器使用 `tools/route_stations.json` 维护各次线路的沿途车站，根据原始日志生成对应轨迹与站点位置；仅更新线路图不改变速度采样和时间标记。

`samples` 的每个元素为 `{t, v, a}`：UTC Unix 毫秒时间戳、km/h 速度、km/h 速度不确定度。`events` 的每个元素为 `{id, name, type, start, end}`，`type` 为 `pass` 或 `stop`，起止为 UTC Unix 毫秒时间戳。页面显示北京时间 UTC+8，支持跨日期。

经记录者要求事后推算的标记额外保存 `source: "inferred"`、说明 `note` 与公开资料链接 `reference`。区间列表和悬停详情仅显示“事后推算”标签，不展示推算说明；导出数据保留这些字段，离线网页采用相同展示方式。G1985 的高邮北、G797 的滕州东和枣庄标记采用该来源标识。

C2123 的永乐通过区间同样标为“事后推算”：利用 C2613 与 C2568 实测永乐边界的原始 GNSS 位置映射到本次轨迹，四舍五入到秒为 2026-10-18 18:55:34—18:55:40；方法与交叉核对结果存于标记 `note`。该计算采用本地日志，不依赖公开资料链接。

曲线保留原始采样，不做平滑。超过正常采样间隔 1.5 倍的间断留空。色带为速度 ± 设备报告的速度精度（约 68% 置信水平），下限取 0。
